# Authenticated client catalog (increment, not Android enrollment)

A new `catalog` control request runs over the existing authenticated iroh connection.
It has **no environment-list or peer-id argument**. The server uses the connection's
remote endpoint id, requires its current `t3` grant, and then a separate explicit
allowlist of environment IDs in `client-catalog.json`. No catalog is available by
pairing alone, by public gateway access, or by knowing a desktop URL.

The client API is `Client::catalog(&EndpointAddr)`. A response is bound to the actual
server endpoint and local client id. Export/reconcile use the common lib-t3-rust
contract (pinned commit), not copied JSON policy in the application. Existing framed
control limits (64 KiB) apply. Unauthorized requests all receive `Denied`, with no
labels, routes, secrets or internal file errors.

## Desktop publisher integration

`catalog::publish_source(&Store, &Value)` is a local single-writer integration API.
It atomically publishes sanitized environments, descriptor-verified portable endpoints
and explicit client grants as one 0600 file. A file lock prevents concurrent revision
loss. Revisions must increase. The source must be generated by the authorized desktop
publisher, not accepted from a remote catalog reader. Each listed client must already
have a current `t3` service grant. No default allow-all, transitive peer discovery,
public listener, admin grant or productive configuration is created.

Source shape (synthetic identities here; a real client key is 64 lowercase hex):

```json
{"version":1,"revision":1,
 "environments":[{"id":"00000000-0000-4000-8000-000000000001","name":"HOST","enabled":true}],
 "endpoints":[{"environmentId":"00000000-0000-4000-8000-000000000001","descriptorEnvironmentId":"00000000-0000-4000-8000-000000000001",
  "id":"public-gateway","url":"https://host.example.com/","priority":0}],
 "clients":{"<authenticated-phone-endpoint-id>":["00000000-0000-4000-8000-000000000001"]}}
```

The native desktop adapter must obtain `connection_catalog::view`, resolve local aliases
to descriptor UUIDs, verify route descriptors and publish whenever authorized metadata,
routes or grants changes. That adapter is not provided in this increment. Never dump
Electron's catalog or private T3 credentials into this source. Root/row/endpoint fields
are allowlisted; portable URLs and descriptor identity are validated in the shared lib.
The private source is read on every request, so changed grants/routes and revocations
apply to subsequent reads without restarting a daemon. A revoked peer's request is
rejected even if the private publication file has not yet been rewritten.

## Remaining Android and authorization work

This is metadata discovery, NOT a T3 session. It cannot show HOST threads by itself.
The Android native bridge client/enrollment path still needs to expose this client API,
then call the shared reconciler/cache adapter. A T3 grant on one host does not authorize
another host. Client-specific bounded T3 sessions/capabilities must be delegated by the
existing server authority, with per-environment scope/lifetime/revocation; never copy
desktop private tokens. No new token format or permissive proxy is invented here.

Tests exercise the real loopback QUIC protocol with independent temporary device
identities: no pairing, pairing without catalog grant, explicit GATEWAY+HOST view,
unauthorized second client, withdrawal, new HOST route, restoration and revocation.
The underlying T3 TCP listener is never opened by discovery. Data and routes are
synthetic; these tests do not claim live hosts, Android JNI, threads or physical sync.
This source/API is not deployed or published as a service by the test.
